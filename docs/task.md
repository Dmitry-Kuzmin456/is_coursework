# Информационные системы. Курсовая работа

## Цель курсовой работы

Получение навыков и знаний, необходимых для создания информационной системы в заданной предметной области.

## Команда

Не более 2 человек.

## Порядок выполнения курсовой работы

> При демонстрации каждого этапа требуется предоставление отчёта.

## Этап 1. Анализ предметной области и проектирование системы

1. Согласовать с преподавателем предметную область, для которой будет разрабатываться информационная система.

2. Составить подробное текстовое описание предметной области.

3. Сформулировать назначение информационной системы:

   - зачем информационная система нужна в выбранной предметной области;
   - какие задачи она позволит решить.

4. Составить функциональные и нефункциональные требования к разрабатываемой информационной системе.

5. Построить модели основных прецедентов и составить их описание.

   > Основные прецеденты необходимо согласовать с преподавателем.

6. Предложить архитектуру будущей системы.

   При проектировании архитектуры необходимо учитывать, что все этапы курсовой работы нужно будет демонстрировать на сервере `helios`.

   Используемые технологии и фреймворки необходимо согласовать с преподавателем.

   Для реализации системы разрешается использовать следующие технологии:

   ### Frontend

   - React;
   - Angular;
   - Vue;
   - Next.js;
   - JSF;
   - Spring MVC с использованием Thymeleaf или другого шаблонизатора.

   ### Backend

   - Jakarta EE;
   - Spring MVC.

   ### База данных

   - PostgreSQL.

7. Составить отчёт по первому этапу.

## Этап 2. Проектирование и реализация базы данных

1. Сформировать ER-модель базы данных на основе:

   - описания предметной области;
   - прецедентов, разработанных на первом этапе.

   ER-модель должна:

   - включать не менее 10 сущностей;
   - содержать хотя бы одно отношение вида «многие ко многим».

2. Согласовать ER-модель с преподавателем.

3. На основе ER-модели построить даталогическую модель базы данных.

4. Реализовать даталогическую модель в реляционной СУБД PostgreSQL.

5. Обеспечить целостность данных с помощью:

   - ограничений языка DDL;
   - триггеров.

6. Реализовать скрипты для:

   - создания базы данных;
   - удаления базы данных;
   - заполнения базы тестовыми данными.

7. Предложить функции и процедуры на языке `PL/pgSQL` для выполнения критически важных запросов, которые потребуются при последующей реализации прецедентов.

8. Создать индексы на основе анализа использования базы данных в контексте прецедентов, описанных на первом этапе.

9. Обосновать полезность созданных индексов для реализации представленных бизнес-процессов.

10. Составить отчёт по второму этапу.

## Этап 3. Реализация уровней хранения и бизнес-логики

1. Изобразить диаграмму классов, представляющую общую архитектуру системы.

2. Реализовать уровень хранения информационной системы на основе базы данных, разработанной на предыдущем этапе.

3. При реализации уровня хранения должны использоваться функции и процедуры, созданные на втором этапе с помощью `PL/pgSQL`.

   > Нельзя заменять их использование альтернативной реализацией аналогичных запросов на уровне хранения информационной системы.

4. На основе описания бизнес-процессов первого этапа и реализованного уровня хранения разработать уровень бизнес-логики информационной системы.

5. Составить отчёт по третьему этапу.

## Этап 4. Реализация интерфейса и защита проекта

1. Реализовать уровень представления приложения для осуществления бизнес-процессов, описанных на первом этапе.

2. Сформировать итоговый отчёт, содержащий материалы всех предыдущих этапов.

3. Провести презентацию проекта.

## Важное замечание

> При демонстрации этапа курсовой работы вне установленного срока студент может получить только минимальное количество баллов.
