# PostgreSQL Implementation Plan

**Goal:** реализовать текущую ER-модель и три запрошенных пункта этапа 2.
**Spec:** docs/er/README.md, docs/er/remkomstroy.drawio.
**Architecture:** PostgreSQL 14+, схема remkomstroy; 13 сущностей и таблицы связей M:N. DDL отвечает за локальные ограничения и FK, триггеры — за согласованность нескольких таблиц и отсутствие циклов. Версии остаются числовыми атрибутами, без отдельного механизма снимков плана.

## Ограничения

- Пользователь представляет максимум одну компанию; представителей у компании может не быть.
- Не вводить ограничений на число главных представителей и совмещение ролей.
- Не возвращать веса, специализации, лоты, журналы и связь новых работ с запросом.
- Не выполнять изменения в существующей пользовательской БД. Проверять в отдельном временном кластере.

- [x] Заменить db/001_schema.sql; добавить db/002_integrity.sql. Проверить DDL, связи, циклы и изменение связанных данных.
- [x] Добавить create_database.sql и drop_database.sql, установку в существующую БД и описание запуска. Проверить создание/удаление и повторную установку после удаления схемы.

## Review Focus

- Изменение родителя элемента или проекта не должно создавать межобъектные ссылки.
- Нельзя создать циклический граф работ, в том числе обновлением существующего ребра.
- Изменение и удаление записей тоже должны проверяться, а не только INSERT.
- Скрипты не должны удалять существующую базу или таблицы при обычном создании.
- Таблица представителей не должна требовать компанию у каждого пользователя.

Pre-flight: schema → integrity → install/tests; имена таблиц и порядок подключения фиксируются в db/README.md.

## Результаты проверки

- PostgreSQL 14.19, отдельный временный кластер; пользовательские базы не изменялись.
- Старая схема не прошла тест новой модели: отсутствовала таблица roles.
- integrity.sql: все допустимые и запрещённые сценарии прошли.
- concurrency.py: встречная зависимость во второй транзакции отклонена как цикл.
- Отложенные проверки допускают согласованное изменение иерархии до COMMIT.
- Создание, отказ при повторном создании, удаление схемы, повторная установка и удаление базы проверены.
- Проверены имена баз с пробелами.
- Независимая проверка кода обнаружила обход через старую успешную приёмку. Добавлен падавший regression, проверка заменена на результат последней приёмки; полный набор повторно прошёл.
